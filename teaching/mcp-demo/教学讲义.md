# MCP 教学讲义

## 目标人群

- 没写过 MCP 的测试人员
- 只想先理解概念和演示流程的培训学员

## 30 分钟讲法

### 1. 开场 5 分钟

先讲一句白话:

`function call` 像提前写死几个按钮。  
`MCP` 像接了一个标准工具插座。

### 2. 展示目录 3 分钟

让学员知道今天只看 3 个文件:

- [server.py](D:\opencalw\teaching\mcp-demo\server.py)
- [client_demo.py](D:\opencalw\teaching\mcp-demo\client_demo.py)
- [smoke_test.py](D:\opencalw\teaching\mcp-demo\smoke_test.py)

### 3. 运行脚本演示 7 分钟

执行:

```powershell
cd D:\opencalw\teaching\mcp-demo
python .\client_demo.py
```

边跑边讲:

1. 先 `initialize`，表示客户端和服务端握手
2. 再 `tools/list`，看看服务端提供了什么工具
3. 然后 `tools/call`，实际调用工具
4. 再看 `resources/list` 和 `resources/read`
5. 最后看 `prompts/get`

### 4. 交互演示 10 分钟

执行:

```powershell
python .\client_demo.py --interactive
```

现场输入:

- 功能名称: 购物车结算
- 风险等级: high

然后让学员观察返回内容是不是像“测试助手”。

### 5. 收尾 5 分钟

强调:

- `Tool` 负责做事
- `Resource` 负责供资料
- `Prompt` 负责给模板

## 培训师备注

如果学员问“这和 function call 有什么关系”，可以这样回答:

`function call` 更像单个函数调用能力。  
`MCP` 是一套更标准、更通用的接入方式。  
MCP 里面也可以有类似 function call 的工具调用，但范围更大。

## 课后练习

让学员自己改 3 个点:

1. 在 `server.py` 里新增一个工具，比如 `generate_regression_plan`
2. 在 `server.py` 里新增一个资源，比如 `qa://checklists/mobile-smoke`
3. 在 `client_demo.py` 的交互菜单中把新能力加进去
